# 预设:把 j-agy 当编码子代理

> 复制下面的规则到你的 AGENTS.md(或 `.zcode/AGENTS.md`)即可使用。核心原则:**默认主代理自己写代码**,j-agy 只在特定条件下接管实现。

## 何时使用(替换主代理的规则说明)

写代码默认由主代理自己完成。仅在以下任一情况才派给 j-agy(`agy_prompt` / `agy_conversation`):

1. **主代理的内置子代理工具不可用或故障**——报错、被取消、配额问题时直接改派,**不要原地反复重试内置工具**;
2. **保护主上下文**:实现细节繁琐(大批量机械修改、外围脚本),外包出去避免主上下文被实现噪声淹没;
3. **用户主动要求**本次任务或本会话把实现交给 j-agy。

## 怎么派发

- `effort` 传 `high`;`mode` 按风险选择:
  - **两段式(推荐)**:先 `mode: "plan"` 让它出方案,主代理审过方案后再用 `agy_conversation` + `mode: "accept-edits"` 执行;
  - 机械批量修改可直接 `accept-edits` 一步到位。
- 任务描述必须自包含,缺一样就别派:

```text
目标:<改什么、为什么>
范围:<涉及文件/目录,绝对路径;明确不允许动的部分>
约束:<遵循的现有风格、不得引入的依赖>
验收:<跑什么命令、看到什么结果算完成>
完成后报告:改了哪些文件、每处改动的意图、验收命令的实际输出。
```

## 主代理的验证义务

- 子代理报告「完成」**不构成完成**:主代理必须亲自读 diff、跑验收命令,失败就 `agy_conversation` 打回重做;
- 探索/检索可以放心外包,实现的外包必须配套验证,两者不要混用同一套信任级别。

## 安全

- `skip_permissions` 默认 `true`(自动改文件、跑命令),配合 `sandbox` 使用;
- 敏感项目(生产配置、密钥相关)派发时显式传 `mode: "plan"` 或 `skip_permissions: false`,不要让它带权限自动执行。
