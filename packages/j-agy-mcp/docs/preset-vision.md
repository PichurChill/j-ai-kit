# 预设:把 j-agy 当识图后端

> 复制下面的规则到你的 AGENTS.md(或 `.zcode/AGENTS.md`)即可使用。核心原则:**有眼睛先用眼睛**——主模型有多模态输入就自己看图,j-agy 只做替补。

## 何时使用(替换主代理的规则说明)

仅在以下任一情况才用 j-agy(`agy_prompt`)识图:

1. **主模型无多模态输入**:纯文本模型,原生读不了图片;
2. **原生识图失效**:图片读不了、工具报错、返回内容明显降质到不可用;
3. **原生识别失败**:同一问题原生看不出答案或多次识别结果矛盾;
4. **用户主动要求**本次任务或本会话用 j-agy 识图。

## 能力边界(已实测)

- AGY(Gemini 系,多模态)能通过文件读取工具打开本地图片并描述内容:场景描述、UI 布局盘点、图内文字识别、找元素都可用;
- **不适合**:精确像素坐标与色值(模型给出的是模糊描述,「大概在右上」不能写进代码)、超长截图的逐字 OCR(需要分段时在任务里明确要求先裁切);
- 图片路径必须用绝对路径,并在任务里明确「用文件读取工具打开这张图片」。

## 怎么派发

- 工具:`agy_prompt`;`effort` 一般传 `medium`。

```text
用你的文件读取工具打开本地图片:<绝对路径>
任务:<开放式描述,如 "描述这张截图的界面布局与所有可见文字">
要求:开放式回答,不要假设;看不清或不确定的部分明确说「不确定」,不要猜测补全。
```

## 注意

- **用开放式提问**:「描述画面里有什么」;不要引导式提问(「是不是有红色按钮?」会诱导模型确认不存在的东西)。
- 像素级真值(精确坐标、hex 色值)AGY 给不了,需要时改用专门的像素工具,不要拿它的模糊描述写代码。
