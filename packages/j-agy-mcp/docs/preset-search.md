# 预设:把 j-agy 当搜索后端

> 复制下面的规则到你的 AGENTS.md(或 `.zcode/AGENTS.md`)即可使用。核心原则:**不强制**——内置搜索优先,j-agy 只做替补。

## 何时使用(实测校准的降级链)

搜索遵循固定降级链:**内置 WebSearch → j-agy → WebFetch 抓站**。主代理的 WebSearch 出现以下任一情况时,**直接派发 j-agy**:

1. 内置搜索不可用:额度用完(如 429 limit exhausted)、报错、未配置;
2. 内置搜索故障:连续失败或空结果;
3. 内置搜索结果不满意:换关键词重试后仍搜不到、明显过时或不可信;
4. 用户主动要求本次/本会话用 j-agy 搜索。

**不要用 WebFetch 抓固定网站代替派发**——实测中缺了这条说明,主代理会各自解读:有的正确派发、有的自己抓新闻站绕路,行为不一致且体验破碎。抓站更慢、覆盖面窄、不是真搜索,只作为 j-agy 也失败后的最后手段。

补充:j-agy 背后的 AGY 是独立进程、独立网络出口。主代理侧网络受限时它可能仍然可用,因此「自带搜不到」时它是天然的第二出口,而不是平行的重复选项。

> **ZCode 用户注意**:ZCode 对单次工具调用有 30 秒硬超时(不可配置),而真实搜索任务 AGY 要跑数分钟——同步调用 `agy_prompt` 必然超时。两种解法:走子代理路线并让子代理以 `background: true` 启动任务、用 `agy_status` 轮询(需 j-agy-mcp ≥ 1.1.0,见 `docs/agents/search-agent.md`);或在主代理直接调用时显式传 `background: true`。

## 怎么派发

- 工具:`agy_prompt`;`effort` 一般传 `medium`,深度调研传 `high`。
- 任务描述必须自包含(AGY 看不到主代理的对话),按下面的模板写:

```text
搜索:<主题 + 要回答的具体问题>
要求:
- 使用 web 搜索,关键结论交叉核对至少 2 个独立来源
- 返回要点清单,每条附来源 URL 与内容日期
- 区分「有来源的事实」与「你的推断」,推断要标注
- 搜不到就明确说"未找到",并附上你尝试过的关键词,不要编造
```

## 结果怎么消费

- 来源 URL + 日期是核验抓手:要写进交付物的结论,主代理抽查 1–2 条原文再采信,不直接照单全收。
- AGY 返回「未找到」时,先换主代理自己再试一次内置搜索,仍失败再向用户说明,不要反复重派同一任务。
