# 预设:把 j-agy 当搜索后端

> 复制下面的规则到你的 AGENTS.md(或 `.zcode/AGENTS.md`)即可使用。核心原则:**不强制**——内置搜索优先,j-agy 只做替补。

## 何时使用(替换主代理的规则说明)

搜索一律优先使用会话内自带的搜索工具(WebSearch / WebFetch / 搜索类 MCP)。仅在以下任一情况才改用 j-agy(`agy_prompt`)搜索:

1. **自带搜索不可用**:对应 MCP 额度用完、调用报错、未配置;
2. **自带搜索故障**:连续失败或返回空结果;
3. **自带搜索结果不满意**:搜不到目标、结果明显过时或不可信,换关键词重试后仍不满意;
4. **用户主动要求**本次任务或本会话用 j-agy 搜索。

补充:j-agy 背后的 AGY 是独立进程、独立网络出口。主代理侧网络受限时它可能仍然可用,因此「自带搜不到」时它是天然的第二出口,而不是平行的重复选项。

## 怎么派发

- 工具:`agy_prompt`;`effort` 一般传 `medium`,深度调研传 `high`。
- 任务描述必须自包含(AGY 看不到主代理的对话),按下面的模板写:

```text
搜索:<主题 + 要回答的具体问题>
要求:
- 使用 web 搜索,关键结论交叉核对至少 2 个独立来源
- 返回要点清单,每条附来源 URL 与内容日期
- 区分「有来源的事实」与「你的推断」,推断要标注
- 搜不到就明确说"未找到",并附上你尝试过的关键词,不要编造
```

## 结果怎么消费

- 来源 URL + 日期是核验抓手:要写进交付物的结论,主代理抽查 1–2 条原文再采信,不直接照单全收。
- AGY 返回「未找到」时,先换主代理自己再试一次内置搜索,仍失败再向用户说明,不要反复重派同一任务。
